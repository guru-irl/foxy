# Foxy 3.2.0: layouts per width, corner resize, switch to open tab, agent bridge

Date: 2026-10-04. User feedback on 3.1.1. Builds on
`2026-10-03-foxy-grid-design.md` (§1 to §12 still apply where this spec does
not change them).

## 1. Corner resize

- Every tile has a resize handle in each of its four corners: a 16 × 16 px
  hit area inside the tile, invisible, with the matching diagonal cursor.
  Corner handles win over the header drag inside their squares. Handles are
  not tabbable (as before).
- Dragging a corner moves that corner; the opposite corner stays fixed. The
  tile's box follows the pointer freely; the outline shows the snapped
  rectangle: the moving corner snaps to the nearest cell corner, then the
  minimum size (§3 of the grid spec) applies with the opposite corner fixed,
  then the rectangle is clamped to the columns and to row 0.
- Outline, corner dots, sliding neighbours, release, cancel and save rules are
  the grid spec's §11.3 and §12, unchanged.

## 2. Layouts per width

### 2.1 Model

- A **layout** is a set of tile rectangles for one grid width `k` (grid
  columns after the TABS rail). The window's grid width is `c`.
- Storage (`storage.sync`): one key per tile per layout, `tile:<k>:<id>` →
  `{x, y, w, h}`; plus one key per layout, `layout:<k>` → `{ t: lastWriteMs }`
  (separate keys, so two devices writing different layouts never lose each
  other's entry; a layout without its key counts as `t = 0`).
- **Last use** of a layout = the later of its `t` and the last time this
  device showed it as a source (`storage.local` `layoutsShown` →
  `{ "<k>": ms }`, updated at most once a minute per layout).
- **At most 4 layouts.** After a write succeeds, while more than 4 layouts
  exist (also after a sync merge), remove every key of the least recently
  used one, never the one this window uses (ties: smaller `k`).
- **Source layout** for a window: the layout with `k = c`; else the
  smallest wider layout that §2.2 can show by keeping or squeezing (not by
  packing stacks), since it fills the width; else the largest narrower
  layout; else the smallest wider layout. No layouts at all: the window
  creates layout `c`.

### 2.2 Display

- `k ≤ c`: `fit(layout, c)` (§12 of the grid spec; with `k < c` the layout
  shows as saved unless saved tiles overlap).
- `k > c`: `derive(layout, k, c)`:
  1. `N = fit(layout, k)` (separates any overlapping saved tiles).
  2. **Keep the arrangement:** run grid spec §12 steps 2 to 4 on `N` with
     `c` columns. If no tile is set aside, show that.
  3. **Squeeze:** map every column boundary `b` of `N` (0 to its right edge
     `e`) to `round(b × c / e)`; each tile `[x, x + w)` becomes
     `[map(x), map(x + w))`, rows unchanged. Order is kept, so tiles stay
     clear of each other. Show this if every tile keeps at least its minimum
     width and at least `round(0.7 × w)` columns.
  4. **Otherwise pack stacks:**
     - A **stack** is a set of tiles whose column ranges `[x, x + w)` overlap,
       joined transitively. Its box is the bounding box of its tiles; each
       tile keeps its offset inside the box.
     - A stack wider than `c` is rearranged inside itself with
       `fit(tiles, c)` first.
     - Stacks in order of their left edge (then top edge) go to the lowest
       row, then the leftmost column, where their box does not overlap the
       boxes already placed.
  This keeps columns of tiles (like the clock above PINNED, or COVERAGE above
  HARNESS) together and in order, with no tiles scattered to the bottom.

### 2.3 Writes

- **Resizing a window or changing the rail width writes nothing.**
- A move, resize or tab drop (after its folder mapping) writes to a
  **target layout**:
  - `k = c`: target `k`; writes `gestureWrites(shown, layout, placed)`.
  - `k < c`: if every visible tile of `placed` ends at or before column `k`,
    target `k` with `gestureWrites`; otherwise target `c` with every visible
    tile of `placed` (a new layout for this width).
  - `k > c`: target `c` with every visible tile of `placed` (a new layout for
    this width). The wider layout is not changed.
  - A release that changes nothing on screen writes nothing (unchanged).
- **Held and pending writes:** every held write and pending `local:*`
  placeholder write records its target layout at release. A gesture creating
  a layout records the full set of visible tiles with it. When folder mappings
  arrive, those placeholders are written with mapped ids to the recorded
  target, never to the current source. If that target was evicted or reset
  meanwhile, the pending write is dropped. Reset also drops held moves.
- **New tiles** (first seen, nothing saved for them in the source layout) are
  placed in the source layout with `addMissing` in `k` columns and written to
  it (as before, after a valid `foxy:saved` reply). With no layouts, the
  window's layout `c` is created this way.
- A layout created from a window only holds that window's visible tiles.
  Hidden tiles and closed groups get a place in it when they first show there
  (new tile rule).
- Each write also sets `layout:<target>` to `{ t: now }`, in the same `set`.
- **Reset layout** removes every `tile:` and `layout:` key (legacy keys
  included).
- **Pruning:** a deleted saved group's tiles are removed from every layout;
  the old 400-key rule counts all tile keys.

### 2.4 Migration

- Legacy keys `tile:<id>` (3.0.0 to 3.1.1) are copied into layout
  `k0 = max(x + w)` over the legacy tiles (one `set` of `tile:<k0>:<id>` and
  `layout:<k0>`) at the first writable publish, **only when no per-width
  layout exists yet**.
- Legacy keys are never removed by migration and are ignored once per-width
  layouts exist, so a device still on 3.1.1 keeps its own arrangement and
  the two versions never undo each other. Reset and pruning remove them.

## 3. Switch to an open tab

- Synced setting `switchToOpenTab`, default on: "Switch to an open tab
  instead of opening a duplicate" (WINDOWS section of the pane).
- **Candidates:** a tab created active (in the foreground), during its first
  10 seconds, each time its URL changes to an `http:` or `https:` URL, until
  its first load of a web page completes (a completed `about:blank`, which
  Firefox reports first for tabs opened from other apps, does not count).
  The check runs as soon as the URL arrives; there is no waiting period.
- **Skipped:** tabs in a burst: 3 or more tabs created within 1 second,
  counting tabs created before and after this one up to the moment its URL
  is checked (session restore and open all in tabs create every tab before
  any URL arrives);
  tabs created in the first 15 seconds after the browser starts (the start
  time survives the background going idle: kept in `storage.session`); tabs
  Foxy creates itself (sync, reopen, agent bridge); background tabs; tabs in
  popup windows (and matches in popup windows).
- **Close:** the new tab is closed the way Foxy's own page closes itself
  (`blankAndClose`), so it does not fill Recently Closed and Ctrl+Shift+T
  still reaches the user's earlier closed tabs.
- **Match:** another tab in any window with the same private state and
  container (`cookieStoreId`) whose URL equals the new URL ignoring the
  fragment (`#…`). Pinned tabs and tabs in groups (collapsed or not) count.
  Several matches: the one in the new tab's window first, then the most
  recently used.
- **Action:** expand the match's group if collapsed, activate the match and
  focus its window, then close the new tab.
- Saved (closed) groups are not searched.
- Accepted trade-off: a tab the user reopens with Ctrl+Shift+T whose URL is
  open elsewhere is switched like any new tab (its back and forward history
  is lost). Telling restored tabs apart needs the `sessions` permission.

## 4. Agent bridge

### 4.1 Pieces

- **Extension:** manifest permission `nativeMessaging`. `src/agent.js` calls
  `runtime.connectNative("foxy_agent")` when the background starts (except on
  Windows). After a disconnect it retries after 5 seconds, then every 60
  seconds while the background runs, silently; a connection that answered a
  request or lasted 5 seconds counts as working, so its next retry is again
  after 5 seconds. The background restarting on any browser event also
  reconnects.
- **Host:** `agent/foxy_host.py` (Python 3 standard library), launched by
  Firefox. It relays requests between a Unix socket and the extension:
  socket `~/.config/foxy/agent.sock` (directory 0700, socket 0600), or
  `$FOXY_AGENT_SOCK` if set. One JSON line per request and per reply; 10 s
  reply timeout. It exits and removes its socket when Firefox closes the
  pipe. A stale socket (no live host) is replaced; a live one is not.
- **CLI:** `agent/foxy` (Python 3):
  - `foxy groups`: open groups (title, colour, window, collapsed, tab count,
    in the last focused window) and saved closed groups.
  - `foxy tabs <group>`: titles and URLs of a group's tabs.
  - `foxy add <group> <url>... [--create] [--color <c>]`
  - `foxy new <title> <url>... [--color <c>]`
  - `--json` on every command. Exit codes: 0 done, 1 refused (with a
    message), 2 Foxy not reachable (Firefox not running, host not installed,
    or Foxy older than 3.2.0).
- **Installer:** `scripts/install_agent.py` writes the host manifest
  (`~/Library/Application Support/Mozilla/NativeMessagingHosts/foxy_agent.json`
  on macOS, `~/.mozilla/native-messaging-hosts/` on Linux) pointing at the
  host with an absolute path, `allowed_extensions` = Foxy's ID; `--uninstall`
  removes it; `--host <path>` overrides the host path (tests).
- **Skill:** `skills/foxy-tabs/SKILL.md`, registered by a symlink
  `~/.agents/skills/foxy-tabs` → the repo folder.

### 4.2 Commands (extension side)

- Group names match case-insensitively after trimming. Several open groups
  with the name: the one in the last focused normal window, else the lowest
  window ID.
- **add:** open group: create the tabs inactive in the group's window and add
  them to the group; skip URLs already in that group (fragment ignored).
  Saved closed group: add bookmarks to its folder (skip duplicates); it stays
  closed. No match: refuse with the list of group names, unless `--create`.
- **new:** create a group in the last focused normal window from inactive
  tabs, with the title and colour (Firefox's default colour when omitted).
  Foxy's sync saves it like any other group.
  A name matching an open group by the same rules is refused (exit 1), suggesting `add`.
- **Limits:** at most 50 URLs per request; only `http:` and `https:` URLs;
  titles up to 200 characters; colours from Firefox's tab group colours.
- Tabs the bridge creates are marked so §3 never closes them.
- Nothing the bridge does focuses a window or changes the active tab.

## 5. Not included

- Hiding the pinned tabs in Firefox's sidebar (waiting on the user; the
  board's PINNED tile already has a Show pinned setting).
- Agents removing tabs or groups.
- Searching saved groups for §3.

## 6. Testing

- Pure: `derive` (keep path, stack packing, the user's real 34-column layout
  at 17 and 33 columns, wide stacks, overlaps, determinism, no overlaps and
  inside columns as a seeded property), source layout choice, target layout
  choice, migration.
- Browser: corner resize from each corner (free follow, outline, minimum size
  with the opposite corner fixed, clamping); per-width layouts across window
  widths (a 17-column edit does not change the 34-column layout; widening
  back shows it unchanged); new tiles; Reset; eviction of the fifth layout.
- Background: switch to open tab (each skip rule, containers, private,
  collapsed group expand, several matches, redirect chain, setting off).
- Agent: host framing and relay (Python, fake extension), CLI exit codes,
  command handling with the fake Firefox (open, saved, missing, ambiguous,
  limits, duplicates, no focus change), and an end-to-end smoke run with
  headless Firefox, the installed host manifest and `$FOXY_AGENT_SOCK`.
