# Foxy 4.0: widgets bar, kanban, ungrouped rail

Date: 2026-11-01. Replaces the free grid of 3.0 to 3.3: cells, corner resize, free placement and layouts per width.

## User request

"the layout grid situation is just utterly fucked. We'll have one bar on the left like ungrouped tabs where all the widgets can go. one bar on the right for ungrouped tabs as it is. The middle section should be for the kanban. The tiles should be autosorted row by row based on available space. All the kanban tiles should have a fixed width (idk available space/4, or /3 /2 based on available space). The middle section should be scrollable. The saved section should show up in widgets. We dont need to be able to resize the width of kanban tiles, only length."

## 1. Page

- Three columns, edge to edge as today, 16 px gaps (`--gap`):

  | Column | Holds | Width |
  |---|---|---|
  | Widgets bar (left) | the widgets | resizable |
  | Kanban (middle) | group tiles | the rest |
  | Ungrouped tabs rail (right) | as in 3.3, gear inside its bottom right | resizable |

- Each column scrolls vertically on its own, with the existing 20 to 24 px fade masks at scroll edges. The page itself never scrolls.
- **Bar widths:** both are resized by dragging their inner edge (the widgets bar's right edge, the rail's left edge).
  - Both are stored in px in synced settings: `widgetsWidth` (default 304) and `railWidth` (default 304).
  - Range 240 px to a third of the page width.
- **Narrow pages:** each bar is first clamped to its range. If the kanban would then be narrower than 200 px, the widgets bar moves into the kanban column, above the group tiles, at full width and in the same scroll. The rail stays.

## 2. Widgets bar

- **Contents:** clock, pinned, saved, memory and weather, each shown when its Settings toggle is on. SAVED moves here from the board.
- **Shape:** widgets stack top to bottom at full bar width, with 16 px gaps and 12 px corners, on the same glass card as today.
- **Order:** drag a widget by its header or empty space (the weather tile by its body, as today) and drop it between widgets. An insertion line shows where it will land. Default order: clock, pinned, weather, memory, saved.
- **Height:** each widget has a bottom-edge handle (the full-width bottom 8 px, `ns-resize`) that sets its height in px.

  | Widget | Default height | Minimum |
  |---|---|---|
  | Clock | 160 | 112 |
  | Pinned | fits its icons, up to 3 rows | one row |
  | Saved | fits its rows, up to 8 rows | header + 1 row |
  | Memory | 360 | the 3.3 minimum height |
  | Weather | 304 | 112 |

  A height of null means "default": it follows content and width.
- **Contents adapt:** each widget renders from its own box size with the existing container queries. Weather tiers, memory insets and pinned icons keep their 3.3 behaviour at the new sizes.
- **Pinned:** 1×1 icons flow left to right in rows; icon size and spacing as in 3.3.

## 3. Kanban

- **Contents:** group tiles only. This window's groups come first, then other windows' groups, labelled as today, when Other windows is on.
- **Columns:** `n = clamp(floor((W + 16) / (300 + 16)), 1, 4)`, where W is the kanban width. Tile width is `(W - (n - 1) * 16) / n`. Widths are never set by the user.
- **Placement:** tiles are placed in kanban order, each into the column whose bottom is highest so far, leftmost on ties. That reads row by row and leaves no holes. Placement is pure and deterministic given widths and heights.
- **Height:**
  - Counted in tab rows (`--row`: 32 px, or 24 px compact) plus the header.
  - The default is null, meaning fit content between 3 and 12 rows.
  - A bottom-edge handle sets an explicit row count, from 2 to 40. Double-clicking the handle returns to null.
  - Tab lists scroll inside the tile when the height is shorter than the content.
- **Order:**
  - Drag a tile by its header and drop it between tiles; an insertion indicator shows where.
  - Keyboard: with a header focused, Alt+ArrowUp/Down/Left/Right move the tile one place earlier or later in the order.
  - New groups are added at the end. Groups that no longer exist drop out of the order on the next write.
- **Kept from 3.3 (drag and drop):** tabs can be dragged between groups, to the rail and to PINNED. Dropping on empty kanban space creates and names a group.
- **Removed:** corner and width resize, free placement, cell previews, and corner dots.

## 4. Stored data

- **One synced key, `board`:**

  ```js
  board = {
    order: string[],
    heights: { [id]: number },
    widgets: [{ kind, h }],
    t: number,
  }
  ```

  - `order` lists group ids (`group:<folderId>`; local-only groups use `local:<groupId>` and are never stored).
  - `heights` holds row counts; missing means default.
  - `widgets` holds every widget kind in order, each with a px height or null.
  - `t` is the write time. Last write wins across devices.

- **Writes:**
  - Writes come only from gestures (reorder, resize, bar resize, Reset layout).
  - Window resizes and renders never write.
  - Unknown ids are kept until pruned: an id is pruned when its group is neither open nor saved on this device for a whole render cycle. This is the same idea as 3.x pruning.
  - The object stays far below the 8 KB per-item sync limit; cap it at 400 ids, dropping the oldest unknown ids first.
  - Sync writes also cap the UTF-8 JSON key and value at 7,600 bytes: evict oldest unknown ids with their heights, then known heights from the end of the order, then known ids from the end.
- **Settings:**
  - `widgetsWidth` and `railWidth` (px) are synced.
  - The per-device `cellSize` and `customCell` settings are removed, and the Settings pane loses Cell size.
  - Row density stays per device.
- **Upgrade from 3.x, once per device on first run:**
  - `railWidth = railCells * 48 + (railCells - 1) * 16` if `railCells` is stored. With the default of 5, that is 304.
  - The initial `order` comes from the last-used 3.x layout's group tiles, read top to bottom, then left to right.
  - All `tile:*` and `layout:*` keys and `railCells` are removed from sync storage in one write.
  - The upgrade runs only if `board` is missing. A device still on 3.x keeps working from its local cache; it loses its layouts when the removal syncs. That is accepted.
- **Reset layout** clears `board` and the two widths (two clicks within 3 s, as today).

## 5. Removed code

All of `extension/src/grid/` that serves cells, free placement, per-width layouts, derive, squeeze, pack, corners and pending tile placement. Anything still needed, such as edge-drag helpers or scroll fades, moves into `src/kanban/` or `src/widgets/`.

Remove the matching tests; write new ones for the new behaviour. Remove the 3.2/3.3 README text about cells, layouts per width and corners.

## 6. Unchanged

- Tab, group, pin and saved actions;
- Sync of groups and pins through bookmarks;
- The agent bridge;
- Switch to an open tab;
- Weather and memory data;
- Settings other than those named above;
- Theme, fonts, glass values, no borders or shadows, colour only in small dots.

## 7. Acceptance

- At 2560 px wide, the kanban shows 4 columns. At 1512 px (the MacBook with the Firefox sidebar), it shows 2 or 3 columns, depending on the bar widths.
- Tiles fill row by row with no holes, and the middle column scrolls.
- Widgets live only in the left bar, with SAVED among them.
- Kanban tiles can be made taller or shorter only. Order changes by drag or keyboard and syncs.
- Window resizes never write storage.
- Headless renders exist for 2560×1440, 1512×945 and 1024×768, dark and light, plus a narrow page showing the widgets bar moved into the kanban column.
