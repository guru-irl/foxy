# Foxy bookmark sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep every tab group and pinned tab in a shared `Other Bookmarks/Foxy` folder, and apply changes both ways live (spec §8): tabs → bookmarks (outbound) and bookmarks → tabs (inbound, including Firefox Sync from other devices). Restore pins after a failed session restore, and tell the page which groups didn't come back.

**Architecture:** Background-only modules in `extension/src/sync/`, created by `createSync({ api, … })` and wired in `extension/background.js`. Every handler runs through one serial queue so outbound and inbound never interleave. State lives in `storage.local` (maps and bookkeeping) and `storage.session` (a session marker). Writes are idempotent and compare against the *last synced* URL and title, so a change's direction is always known and echoes do nothing.

**Tech Stack:** Plain ES modules; node --test with `createFirefox()` from `test/fakes/firefox.js`.

**Spec:** `docs/superpowers/specs/2026-10-01-foxy-design.md` (§8 Shared groups and pins, §9 Architecture, §10 Errors, §11 Testing).

## Global Constraints

- No npm or pip installs, no new dependencies.
- Never write to `/tmp`, `$TMPDIR` or `/var/tmp`; scratch goes under the worktree's `.spider/scratch/`.
- Never read `~/.config/liquidfox-newtab/amo.env`, never run `scripts/sign.py`, never contact addons.mozilla.org, never push or create GitHub resources, never touch the real Firefox profile.
- Modules take `api` as a parameter; only `extension/background.js` reads `globalThis.browser`. Listeners are registered at the top level of `background.js` (event page).
- Console messages start with `Foxy:`; API failures are caught and logged, never thrown out of a listener.
- Folder titles use exactly these emoji (spec §8.1): red 🔴, orange 🟠, yellow 🟡, green 🟢, cyan 🩵, blue 🔵, purple 🟣, pink 🩷, grey 🩶; the pinned folder is `📌 Pinned`; the root is `Foxy` under Other Bookmarks (`unfiled_____`).
- Never delete a folder or bookmark because tabs are missing at startup (spec §8.6). The only folder deletion is the explicit `foxy:delete-saved` message.
- Removals during window close or quit (`isWindowClosing: true`) are never written (spec §8.3).
- Not saved: tabs showing `about:newtab`, `about:home`, `about:blank`, or any page of this extension (spec §8.3).
- Tab URLs the add-on doesn't reopen (anything but `http:` and `https:`: `about:`, `file:`, `chrome:`, `data:`, `javascript:`) are skipped on inbound and recorded as "can't reopen" (spec §8.4).
- The safety rule (spec §8.5): never close, move or navigate the active tab of the focused window; defer and retry when it's no longer shown.
- Firefox 157 facts:
  - `tabs.create` rejects `discarded: true` together with `active: true`, with `pinned: true`, or with an `about:` URL (including `about:blank`), and rejects `title` without `discarded: true` (`ext-tabs.js` ~786-806). The fake models these.
  - `bookmarks.onRemoved` fires once for a removed folder, with no events for its children.
  - Sync-applied changes fire the normal bookmark events.
  - `bookmarks.move`'s `index` is the final position.
- `npm test` passes at the end of every task.

## Review Focus

1. **Echo loops.** Outbound writes fire bookmark events, and inbound tab changes fire tab events. Either one must end in a no-op. After any scenario, running the queue again changes nothing.
2. **Whole-group close.** Closing a group closes its tabs one by one before the group disappears. The folder must keep all its bookmarks, and so must quitting Firefox.
3. **A local change racing an inbound pass.** A tab navigated locally must never be sent back to its old URL. Direction comes from `lastSynced`, never from comparing the current values.
4. **Startup with changed ids.** After a restart, tab and group ids are new. Matching by name, colour and URL must not create duplicate folders or reopen tabs that are already open.
5. **The safety rule** under every inbound action (close, navigate, move), including deferral surviving the background page's restart (it's stored).

```js
export const PINNED_TITLE = "📌 Pinned";
export const COLOR_EMOJI;   // { red: "🔴", orange: "🟠", yellow: "🟡", green: "🟢", cyan: "🩵", blue: "🔵", purple: "🟣", pink: "🩷", grey: "🩶" }

export function decodeFolderTitle(text): { title: string, color: string }   // tolerant: VS16 (U+FE0F) after the emoji, extra spaces; no known emoji → { title: text.trim(), color: "grey" }
export function isPinnedFolderTitle(text): boolean           // "📌 Pinned", with or without VS16
export function isSyncableUrl(url, extensionBaseUrl): boolean // false for about:newtab, about:home, about:blank, empty, and URLs starting with extensionBaseUrl

// tree.js
export const OTHER_BOOKMARKS = "unfiled_____";
export async function findOrCreateRoot(api, knownRootId): Promise<string>
//   1. the oldest (dateAdded, then index) folder titled ROOT_TITLE directly under OTHER_BOOKMARKS
//      (so two devices that both created a root before Sync merged converge on the same one);
//   2. else knownRootId if it still exists as a folder (the user renamed or moved it);
//   3. else create it at the end of OTHER_BOOKMARKS.
export async function findExtraRoots(api, rootId, knownRootId): Promise<string[]>  // knownRootId first when it is a live folder other than rootId (renamed or moved by the user), then the other ROOT_TITLE folders directly under OTHER_BOOKMARKS, oldest first
export async function ensurePinnedFolder(api, rootId): Promise<string>   // first child folder with isPinnedFolderTitle, else create at index 0
export async function readTree(api, rootId): Promise<{ pinned: FolderInfo|null, extraPinned: FolderInfo[], folders: FolderInfo[] }>
// FolderInfo = { id, index, title, color /* decoded */, name /* decoded title */, bookmarks: Array<{ id, index, url, title }> }
// pinned = the first child folder (by index) with isPinnedFolderTitle; extraPinned = any later ones (a second device's first run before Sync merged);
// folders exclude every pinned-titled folder; bookmarks and separators directly under the root are ignored; nested folders and separators inside a group folder are ignored
```

### Task 3: Outbound (tabs → bookmarks)

**Files:**
- Create: `extension/src/sync/outbound.js`, `test/sync-outbound.test.js`

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces: `createOutbound({ api, getState, save, now, removeDelayMs = 2000, quietMs = 10000, extensionBaseUrl })`. It returns an object with:
  - `syncTab(tabId): Promise<void>`
  - `syncGroup(groupId): Promise<void>`
  - `tabRemoved(tabId, removeInfo): void` (schedules a removal)
  - `groupRemoved(group, removeInfo): Promise<void>`
  - `flush(): Promise<void>`, which runs due removals now (tests; Task 5 also calls it inside the queue on every wake)
  - option `schedule(delayMs)`, called whenever a removal is scheduled; Task 5 passes `ms => setTimeout(() => queue.run(() => outbound.flush()), ms)` (not awaited)

  `getState()` returns the live state object, and `save()` persists it. Callers (Task 5) run all of these inside the queue.

Rules (spec §8.3):
- **`syncTab(tabId)`:**
  1. Read the tab (a missing tab means return).
  2. Work out the target folder: `pinnedId` if the tab is pinned; the group's folder if it's grouped (call `syncGroup` first if the group isn't mapped yet); otherwise none.
  3. If there's no target folder (the tab left its group or was unpinned) or it's a different folder than the entry's, treat the existing entry as a removal: go through the delayed, guarded removal below. If the URL isn't syncable but the tab is still in the entry's folder, write nothing and keep the entry.
  4. Position in a group folder: a new bookmark goes right after the bookmark of the nearest earlier tab in the same group that has an entry (otherwise index 0); an existing one stays put while it sits after that bookmark and before the nearest later mapped tab's bookmark, otherwise it moves right after the earlier one (index 0 when none). Unmapped bookmarks between mapped ones never cause moves. In the pinned folder (shared by every window): a new bookmark goes right after the nearest earlier same-window pin's bookmark, otherwise at the end; an existing one moves only if it sits before that bookmark (then right after it), and never when the tab has no earlier same-window pin. Only the relative order within a window is kept, so windows never fight.
  5. With no entry, create the bookmark there and store `{ bookmarkId, folderId, url, title }`.
  6. With an entry whose bookmark is gone, do nothing (inbound owns that case).
  7. With an entry whose bookmark is in the wrong folder or position, `bookmarks.move` it and update `folderId`.
  8. If `tab.url !== entry.url` and the tab isn't quiet (`quietUntil[tabId] > now()`), and `tab.status === "complete"`: `bookmarks.update(url, title)` and record both.
  9. Otherwise, if only the title differs from `entry.title` and the tab is complete: update the title.
- **Removal** (`tabRemoved` without `isWindowClosing`, or `syncTab` finding the tab left its folder): after `removeDelayMs`, check whether the folder still has a live group: `groupOfFolder` is mapped and `tabGroups.get` resolves, or the folder is `pinnedId`.
  - If so, `bookmarks.remove(entry.bookmarkId)`, ignoring a missing bookmark.
  - If not, remove nothing.
  - In both cases delete the entry. With `isWindowClosing`, delete nothing and write nothing.
- **`syncGroup(groupId)`:**
  - If the group isn't mapped: create a folder `encodeFolderTitle(group)` at the end of the root, map it, add it to `openFolders`, then `syncTab` each member in order.
  - If it's mapped and `encodeFolderTitle(group) !== entry.title`: `bookmarks.update(folderId, { title })` and record it.
- **`groupRemoved(group, removeInfo)`:** unmap the group. Unless `isWindowClosing`, take its folder out of `openFolders`. Never touch bookmarks.

### Task 4: Inbound (bookmarks → tabs) and the safety rule

**Files:**
- Create: `extension/src/sync/inbound.js`, `test/sync-inbound.test.js`

**Interfaces:**
- Consumes: Tasks 1–3 (the state layout).
- Produces: `createInbound({ api, getState, save, now, quietMs = 10000 })`. It returns an object with:
  - `reconcileFolder(folderId): Promise<void>`
  - `reconcileAll(): Promise<void>` (the pinned folder plus every mapped folder)
  - `folderRemoved(folderId): Promise<void>`
  - `bookmarkMoved(id, moveInfo): Promise<void>`
  - `applyDeferred(): Promise<void>`
  - `isShown(tab): Promise<boolean>`, which is true when `tab.active` is set and the tab's window is the last focused window and `focused`

Rules (spec §8.4, §8.5):
- **`reconcileFolder(folderId)` for a folder mapped to an open group:**
  1. For entries of this folder whose bookmark is gone:
     - if the bookmark now sits in another folder mapped to an open group, `tabs.group` the tab into that group and update the entry;
     - otherwise close the tab and delete the entry.
  2. For bookmarks with no entry, if `isOpenableUrl`:
     - `tabs.create({ windowId: <group's window>, url, title, discarded: true, active: false })`, then `tabs.group` it into the group;
     - move it before the tab of the next mapped bookmark;
     - store the entry with `url` = the bookmark URL and set `quietUntil`.
     If the URL isn't openable, add it to `cantReopen[folderId]` once.
  3. For entries whose bookmark URL differs from `entry.url`: `tabs.update(tabId, { url })`, set `entry.url` and `quietUntil`.
  4. If the folder title differs from the group entry's `title`: `tabGroups.update(groupId, decodeFolderTitle(...))` and record the title.
- **`reconcileFolder` for the pinned folder:**
  - A missing bookmark closes the mapped pinned tab.
  - A new openable bookmark opens pinned in the last focused normal window with `{ url, pinned: true, active: false }` (Firefox 157 rejects `discarded` and `title` for pinned tabs), then `tabs.discard(tabId)` so it stays unloaded; a failed discard is only logged.
  - URL changes navigate the tab.
- **Folders not mapped** (saved here): nothing to do.
- **Safety rule:** every close, move or navigate first checks `isShown`. When the tab is shown, that single action is skipped and the folder id is added to `deferred` (and saved). `applyDeferred()`, which Task 5 calls on `tabs.onActivated` and `windows.onFocusChanged`, reconciles every deferred folder and keeps only those that deferred again.
- **`folderRemoved(folderId)`** (the removal event for a folder mapped to an open group):
  - `tabs.ungroup` its tabs and delete the group mapping and its entries;
  - remove it from `openFolders`, `missing`, `cantReopen` and `deferred`.
  - For the root folder itself, reset `rootId`, `pinnedId`, `groups` and `tabs` (Task 5 then runs `rebuild`).
- **`bookmarkMoved`:** within one mapped folder, move the mapped tab so the tab order matches the bookmark order for that tab (no-op when it already does). Across folders: `reconcileFolder` both.

### Task 5: Startup, background wiring, messages, permissions

**Files:**
- Create: `extension/src/sync/sync.js` (`createSync`), `extension/src/sync/startup.js`, `test/sync-startup.test.js`, `test/sync-messages.test.js`
- Modify: `extension/background.js`, `extension/manifest.json` (permissions `["tabs", "tabGroups", "bookmarks", "storage"]`), `test/manifest.test.js`, `test/fakes/firefox.js` (add `restart({ restore })`, see below)

**Interfaces:**
- Consumes: Tasks 1–4; `handleMessage` from `extension/src/close.js` (existing close message).
- Produces:
  - `createSync({ api, now = Date.now, removeDelayMs, quietMs, settleMs = 3000, maxWaitMs = 20000 })` returns an object with:
    - `start(): Promise<void>`, which runs `startup` once per browser session (the `storage.session` key `foxySession` marks it) and is safe to call on every background wake;
    - `handlers`, an object with one function per registered event (all run through the queue);
    - `onMessage(message): Promise<any>`;
    - `idle(): Promise<void>` (for tests).
  - The messages the page uses (Plan D), and their responses:

| Message | Response and effect |
|---|---|
| `{ type: "foxy:saved" }` | `{ saved: [{ folderId, title, color, count, cantReopen: string[] }], missing: [{ folderId, title, color }] }`. `saved` is every group folder not open on this device, in folder order. `count` is its bookmarks. |
| `{ type: "foxy:open-saved", folderId, windowId }` | Opens the folder as a group in `windowId`: unloaded tabs for openable bookmarks, `tabs.group` with `createProperties: { windowId }`, then `tabGroups.update` with the title and colour. It's mapped before returning, and removed from `missing`. Returns `{ ok, groupId }`. |
| `{ type: "foxy:delete-saved", folderId }` | Only when the folder isn't open here: `bookmarks.removeTree(folderId)` and clean the state. Returns `{ ok }`. |
| `{ type: "foxy:restore-all", windowId }` | `open-saved` for every `missing` folder, then clears `missing`. Returns `{ ok }`. |
| `{ type: "foxy:dismiss-missing" }` | Clears `missing`. Returns `{ ok }`. |
| `{ type: "foxy:reconcile" }` | Runs `reconcileAll`. Returns `{ ok }`. |

  Anything else goes to the existing close handler unchanged.

- `startup.js` exports `settle(api, { settleMs, maxWaitMs, now })`, which resolves after `settleMs` with no tab or group events, or after `maxWaitMs`. It also exports `rebuild({ api, state, outbound, inbound })`:
  1. Find or create the root, then ensure the pinned folder. Merge duplicates without deleting anything: move every child of each `findExtraRoots` folder into the root (group folders keep their bookmarks), and move each bookmark of `extraPinned` whose URL isn't already in `pinned` into `pinned`. The emptied duplicates are left in place (the only deletion is `foxy:delete-saved`).
  2. `readTree`.
  3. `matchGroups` the open groups against the folders and map the pairs. For each pair, `matchTabs` and map with `url` = the tab URL.
  4. Unmatched tabs in matched groups go through `outbound.syncTab`. Unmatched bookmarks in matched folders open through `inbound.reconcileFolder`.
  5. Unmatched open groups go through `outbound.syncGroup`.
  6. `missing` = the previous `openFolders` minus the matched folders, for folders that still exist.
  7. `openFolders` = the matched and new folders.
  8. Pins: `matchTabs` local pinned tabs against the pinned folder. Unmatched bookmarks open pinned (unloaded, as in Task 4: create without `discarded`, then `tabs.discard`) in the last focused window. Unmatched local pins get bookmarks.
- **`background.js`** registers these at the top level, each calling `sync.start()` first and then its handler:
  - `runtime.onStartup`, `runtime.onInstalled`;
  - `tabs.onCreated`, `onUpdated`, `onRemoved`, `onMoved`, `onAttached`, `onDetached`, `onActivated`;
  - `tabGroups.onCreated`, `onUpdated`, `onRemoved`, `onMoved`;
  - `bookmarks.onCreated`, `onChanged`, `onMoved`, `onRemoved`;
  - `windows.onFocusChanged`;
  - `runtime.onMessage`.
  Bookmark events matter only for nodes whose parent (or whose own id) is the root or a direct child of the root.
- **Fake `restart({ restore })`:** keeps bookmarks and `storage.local`, clears `storage.session` and the listeners, and gives every tab and group new ids.
  - With `restore: true`, it rebuilds the same windows, groups, tabs and pins with new ids.
  - Otherwise it leaves one window with one `about:home` tab.
  - It then queues `runtime.onStartup`.
  Add fake tests for it.

### Task 6: Two-device convergence

**Files:**
- Create: `test/fakes/sync-server.js`, `test/sync-devices.test.js`
- Modify: `test/fakes/firefox.js`. Add:
  - `bookmarkChanges(sinceCursor) -> { cursor, nodes }`, the full node for every created or changed id, plus `{ id, deleted: true }` tombstones;
  - `applyRemoteBookmarks(nodes)`, which creates, updates, moves and removes nodes with the given ids and fires the normal bookmark events, as Firefox Sync does.
- Modify: `extension/src/sync/*` only to fix defects these scenarios expose (each fix needs its failing scenario first).

**Interfaces:**
- Produces: `createSyncServer()` returning `attach(ff)` and `syncAll()`. `syncAll()` uploads each attached device's changes since its cursor (last writer wins per id), then downloads the merged tree to every device and runs `await ff.settle()` plus the device's `sync.idle()`.

Scenarios (each runs `syncAll()` until nothing changes, at most 5 rounds, then asserts both devices' layouts and trees):
1. A creates a "Dev" group with 2 tabs. B shows it in `foxy:saved`; B opens it and gets 2 unloaded tabs in a "Dev" group.
2. Both have it open; A adds a tab in the middle. B gets it at the same position.
3. A closes a tab. B closes it. If B's copy is B's shown tab, it's deferred until B activates another tab.
4. A renames and recolours. B's group follows.
5. A navigates a tab (status complete). B's tab navigates, and there's no ping-pong: a second `syncAll()` produces no bookmark changes.
6. A pins a tab. B gets it pinned. A unpins it. B closes it.
7. A closes the whole group. The folder stays, and B's open group is unchanged.
8. A deletes the saved group (`foxy:delete-saved`) while B has it open. B's tabs stay open, ungrouped.
9. A and B each add a different tab to the same group before syncing. Both end with both tabs.
10. A's window closes (`closeWindow`). No bookmark changes are uploaded.
