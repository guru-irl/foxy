# Foxy 3.1.0 Implementation Plan: edge to edge, Android-style drag, gear cell

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the grid fill the page edge to edge with stretched square cells, move the gear into its own bottom-right cell, and make tile moves and resizes follow the pointer freely with a snapped outline, corner dots and sliding neighbours.

**Architecture:** One new pure function (`fitCell`) gives the stretched cell. Tiles switch from CSS Grid placement to absolute positioning from `--x/--y/--w/--h` custom properties, so position changes can slide with CSS transitions. The gesture code keeps its snapping and `place`/`fit` maths and only changes what is shown during the gesture.

**Tech Stack:** as before (MV3 add-on, ES modules, `node --test`, headless Firefox 157 browser tests, Python smoke and previews).

**Spec:** `docs/superpowers/specs/2026-10-03-foxy-grid-design.md` §11 (and §2 to §8 for everything it does not change).

## Global Constraints

- Gap 16 px; tile and pane corners 12 px; cell presets as before, used as targets.
- `cell = (pageWidth + 16) / total - 16`, `total = totalColumns(pageWidth, preset)`; square cells; no outer margins.
- Slide duration about 200 ms; none with `prefers-reduced-motion: reduce`.
- The drop outline is the only outline on the board: 2 px neutral line, faint fill, 12 px corners. Still no borders or shadows elsewhere.
- Saved layout semantics unchanged: commit writes only moved and pushed tiles; all §6 write gates and held-write rules hold.
- Shared rules: `/Users/guru/src/foxy/.superpowers/sdd/2026-10-03-grid/brief-common.md` (new ledger folder for this round: `/Users/guru/src/foxy/.superpowers/sdd/2026-10-03-grid-3.1/`). Hang-prone test runs: use `node --test --test-timeout=60000`, never an external kill.

## Review Focus

1. Fractional cell sizes: snapping, hit testing (tab drops on cells), drag maths and the narrow-window `fit` stay exact; no 1 px gaps or overlaps from rounding (Task A tests).
2. A window resize during a gesture: the gesture cancels or recomputes cleanly; nothing stuck (Task B test).
3. A board update held during a gesture, released after the slide-in animation: no jump, no lost write (Task B test).
4. Rapid target changes (pointer crossing many cells fast): neighbours end where the last target puts them; no transition pile-up (Task B test).
5. The gear cell and pane at narrow widths and with the rail at its minimum (Task A test).
